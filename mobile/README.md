# delivery_app (mobile)

Flutter client for the delivery marketplace app. One codebase serves all four roles —
customer, driver, vendor, admin — routed by the signed-in user's `role` field. See the
[repo root README](../README.md) for the overall project structure and Firebase setup, and
[`CLAUDE.md`](../CLAUDE.md) for architecture notes.

## Prerequisites

- Flutter SDK matching `environment.sdk: ^3.9.2` in `pubspec.yaml`
- Firebase project wiring is already checked in (`lib/firebase_options.dart`,
  `android/app/google-services.json`) — see the root README's Setup section if you need to
  repoint this at a different Firebase project
- A Maps API key for `google_maps_flutter` (live delivery tracking) — see below

## Setup

```
flutter pub get
```

## Run

```
flutter run
```

For local development against the Firebase emulator suite instead of the live project, start
the emulators from the repo root first:

```
firebase emulators:start
```

then run the app as usual — the emulator ports are Auth `:9099`, Firestore `:8080`,
Functions `:5001`, Storage `:9199`.

## Test & lint

```
flutter analyze                 # run after any lib/ change
flutter test                    # run all tests in test/
flutter test test/widget_test.dart --plain-name "AppUser round-trips"   # run a single test
```

## Maps API key

`android/app/src/main/AndroidManifest.xml`'s `com.google.android.geo.API_KEY` meta-data and
`ios/Runner/AppDelegate.swift`'s `GMSServices.provideAPIKey(...)` call both still hold the
placeholder `"YOUR_MAPS_API_KEY_HERE"`. Swap in a real Maps SDK key (Android + iOS enabled)
from the Google Cloud Console before `GoogleMap` widgets will render actual tiles instead of a
blank grey view.

## iOS

`ios/Runner/GoogleService-Info.plist` was not generated by FlutterFire CLI (it can only embed
that file into the Xcode project from macOS). On a Mac, run
`flutterfire configure -p orient-food-9c1e0 -y --platforms=android,ios,web` from this directory
to fill it in before building for iOS.

## Localization

Arabic-first, RTL-aware. Source strings live in `lib/l10n/app_en.arb` and `lib/l10n/app_ar.arb`;
`flutter pub get` regenerates `AppLocalizations` from them (`generate: true` in `pubspec.yaml`,
config in `l10n.yaml`). `l10n_untranslated.txt` lists any English strings missing an Arabic
translation — it should read `{}` when both files are in sync.

## Structure

```
lib/
  features/     # admin, auth, customer, driver, notifications, vendor — screens + providers
  models/       # AppUser, Order, MenuItem, etc.
  routing/      # go_router config, role-based redirect
  services/     # AuthService, FirestoreService, LocationService, PushNotificationService
  core/         # errors, parsing, theme, constants, and other cross-feature utilities
  shared/       # widgets reused across more than one feature
  l10n/         # generated + source .arb localization files
```
